# サイトの更新のしかた（古町100店・酒蔵リスト）

## 仕組み

古町100店と酒蔵リストのページは、**データファイルを編集するだけ**で自動更新されます。

- 古町の店のデータ: `data/furumachi.json`
- 酒蔵のデータ: `data/breweries.json`

GitHubの画面でこのファイルを編集して保存（コミット）すると、数分以内に自動ビルドが走り、ページ・名簿・地図が作り直されてサイトに反映されます。自分のパソコンで作業する必要はありません。

自動ビルドには安全装置があります。**店の数が合わない、座標が入っていない、などの問題があると、ビルドは失敗してページは一切更新されません**（壊れたページが公開されることはありません）。失敗したときは、リポジトリの「Actions」タブを開くと、赤い×の付いた実行にエラーの理由が表示されます。

## 店を入れ替える（古町）

1. GitHubで `data/furumachi.json` を開き、右上の鉛筆アイコン（Edit）で編集画面に入ります。
2. やめる店のブロック（`{` から `}` まで）を削除します。
3. 新しい店のブロックを、同じジャンルの店の並びの末尾あたりに追加します。
4. **合計が必ず100店**になるようにしてください（1店消したら1店足す）。
5. 画面下の「Commit changes」で保存します。

新しい店のブロックは、既存の店のブロックをコピーして中身を書き換えるのが簡単です。

```json
{
  "slug": "newshop",
  "genre": "jp",
  "ja": "店名",
  "en": "New Shop",
  "addr": "新潟市中央区○○通○番町",
  "note_ja": "一言紹介",
  "note_en": "One-line note in English",
  "note_fr": "Note en français",
  "hours": ["17:00–23:00（日曜休）", "5–11 p.m. (closed Sun)", "17 h – 23 h (fermé dim.)"],
  "url": "https://example.com/",
  "rec": null,
  "lat": 37.924000,
  "lng": 139.045000,
  "precision": "district"
}
```

### 各項目の意味

| 項目 | 内容 |
|---|---|
| `slug` | 半角英数だけの識別子。他の店と重複不可 |
| `genre` | `jp`（日本料理・割烹・居酒屋）/ `sushi`（寿司）/ `bar`（バー）/ `soba`（蕎麦・麺）/ `west`（フレンチ・イタリアン・洋食）/ `other`（焼鳥・その他） |
| `ja` / `en` | 店名（日本語 / ローマ字） |
| `addr` | 住所（表示用。番地は入れず「○○通○番町」までが通例） |
| `note_ja` / `note_en` / `note_fr` | 一言紹介（3言語） |
| `hours` | 営業時間の目安を `[日本語, 英語, フランス語]` の順で3つ。不明なら `"—"` |
| `url` | 公式サイトやInstagramのURL。なければ `null` |
| `rec` | 筆者のおすすめ印。通常は `null`。おすすめは `"picks"` / `"money"` / `"shime"` のいずれかで、**合計12店**と決まっています。入れ替えるときは元の店の `rec` を新しい店に移してください |
| `lat` / `lng` | 緯度・経度（下記） |
| `precision` | 番地まで特定できたら `"full"`、通り・番町レベルなら `"district"` |

### 緯度・経度の取り方

新しい店には座標が必須です（座標がないとビルドが失敗します）。

- **Google Maps**: 店の場所を右クリックすると座標（例 `37.924416, 139.044647`）が表示されます。最初の数字が `lat`（緯度）、2番目が `lng`（経度）です。
- **国土地理院の住所検索**（ https://msearch.gsi.go.jp/address-search/AddressSearch/ ）でも住所から座標が取れます。

## リンクだけを変更する

店の公式サイトやInstagramが分かったら、`data/furumachi.json` のその店の `url` 欄を書き換えて保存するだけです。地図のポップアップにも自動で反映されます。酒蔵も `data/breweries.json` の `url` で同じです。

## 酒蔵のデータを直す（`data/breweries.json`）

項目はほぼ同じ考え方です。酒蔵固有の項目だけ注意してください。

| 項目 | 内容 |
|---|---|
| `founding` | 創業年は酒造組合の表記のまま書きます（例：`"西暦1804年"`、不明なら `"不明"`、安政年間なら `"安政年間"`） |
| `tours` | 見学できる蔵は `true`、できない蔵は `false` |
| `brand_ja` / `brand_en` | 代表銘柄。なければ `null` |
| `precision` | `"FULL_ADDRESS"`（番地まで）/ `"STREET"` / `"DISTRICT"` など、座標の精度 |
| `region` | `"下越"` / `"中越"` / `"上越"` / `"佐渡"` |

酒蔵は**合計92蔵**が決まりです。

## 自動ビルドを手動で走らせる

「Actions」タブ →「Build pages from data」→「Run workflow」から、いつでも手動で再生成できます。

## 注意

- JSONは記号に厳密です。項目の終わりのカンマ `,` の付け忘れ・付けすぎ、引用符 `"` の閉じ忘れがあると読み込めません。既存のブロックの形を崩さず、中身の文字だけを書き換えるのが安全です。
- データ以外のページ（トップページ、寿司特集など）はこの仕組みの対象外です。これまで通り別途編集します。
- 仕組みの本体は `scripts/build_site.py` です。データの検証（件数・おすすめ12店・座標・「★」が含まれていないか等）もここで行っています。
